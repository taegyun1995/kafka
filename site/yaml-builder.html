Spring Kafka Configuration Builder

옵션을 선택하면 application.yml을 생성합니다

← 학습 문서로 돌아가기

Producer·Consumer·Listener에 필요한 설정을 선택해 Spring Boot용 YAML을 생성합니다. 생성된 값은 학습·초기 구성용이며, 운영 환경의 Broker 주소·인증 정보는 환경변수나 Secret으로 주입하세요.

QUICK START 상황을 먼저 고르면 옵션이 채워집니다

프리셋은 설정 기반을 만듭니다. 실제 전달 보장은 전송·처리·Commit 코드까지 함께 결정합니다.

01 · SCOPE 생성할 구성 범위

켜면 주소·Group ID·Transaction ID Prefix를 ${NAME:기본값} 형태로 출력합니다. YAML에 실제 비밀번호·Broker 주소를 직접 남기지 않기 위한 선택입니다.

Producer는 발행 Client, Consumer Client는 실제 poll()·Group·Offset 설정, Spring Listener는 그 Consumer를 감싼 Container와 Callback 설정입니다. Spring Listener를 선택하면 Consumer Client 설정도 자동으로 포함됩니다.

Producer 옵션

Retry로 같은 Produce 요청이 재전송되어도 Broker가 Producer Sequence를 사용해 중복 기록을 줄입니다. 애플리케이션의 DB 중복 처리까지 대신하지는 않습니다.

멱등성·Transaction을 사용하면 acks=all과 재시도가 필요합니다. 아래 선택기는 호환되지 않는 조합을 자동으로 보정합니다.

transaction-id-prefix로 Transactional Producer와 Transaction Manager를 구성할 준비를 합니다. 실제 Transaction은 KafkaTemplate.executeInTransaction(...), @Transactional 또는 Transaction이 설정된 Listener Container가 시작해야 합니다. 이 설정만으로 일반 send()가 자동으로 하나의 Transaction에 묶이는 것은 아니며, 외부 DB Commit도 자동으로 원자화하지 않습니다.

Consumer 옵션

켜면 Consumer가 주기적으로 Offset을 자동 Commit합니다. 처리 완료 시점과 Commit 시점을 세밀하게 맞추려면 보통 끄고 Spring Listener의 Ack Mode를 설계합니다.

Spring Listener Container 옵션

Listener를 켜면 Consumer 설정도 함께 생성됩니다. concurrency는 이 애플리케이션 인스턴스의 Listener Container가 만드는 Consumer 실행 단위 수이며, 전체 Group 멤버 수는 애플리케이션 인스턴스 수와 함께 계산해야 합니다.

02 · OUTPUT application.yml

생성 결과는 Spring Boot 설정입니다. Broker의 server.properties가 아니라 애플리케이션 Client 설정에 해당합니다. Topic은 @KafkaListener의 topics나 KafkaTemplate 호출에서 별도로 결정합니다.

선택 기준

enable.idempotence는 Producer Retry 중복 방지, read_committed는 Kafka Transaction Output 가시성, ack-mode는 Spring Listener의 Commit 시점을 결정합니다. read_committed만으로 Consumer EOS가 만들어지지 않으며, Transaction 설정만으로 외부 DB까지 한 Transaction으로 묶이지도 않습니다.
