PopupPass / Guards

보호 장치를 하나씩 켜 본다

지금 코드에는 선착순을 지키는 장치가 세 겹 있다. 다 켜 놓고 보면 무엇 덕분에 막혔는지 알 수 없으므로, 아무 보호도 없는 0단계부터 하나씩 더하며 그때마다 무엇이 깨지는지 본다. 아래 버튼은 실제 서버에서 진짜로 동시 요청을 일으킨다.

0 · 보호 없음 1 · 원자적 차감 2 · 부분 Unique Index 3 · 멱등성 키

경합이 실제로 일어나므로 누를 때마다 숫자가 조금씩 다를 수 있다. 그것이 이 화면의 요점이다. 전용 테이블(study_*)만 쓰므로 실제 예약 데이터와 섞이지 않는다. 무엇을 왜 만드는지는 학습 기획, 현재 구조는 기초 아키텍처에 있다.

01

Connect

서버에 붙는다

학습용 창구는 study 프로필에서만 열린다. 평소 실행에는 없는 코드다.

docker compose up -d postgres 로 DB를 띄우고, gradle bootRun --args='--spring.profiles.active=study' 로 서버를 실행한 뒤 연결한다.

02

Matrix

같은 상황, 다른 단계

가로는 상황, 세로는 단계다. 칸을 누르면 그 단계에 그 상황을 실제로 들이댄다.

BROKEN · 실제로 깨졌다 PARTIAL · 막기는 했는데 대가가 있다 OK · 막혔다
단계별 보호 장치와 상황을 교차한 실행 결과
03

Last Run

방금 무슨 일이 있었나

판정과 설명은 미리 적어 둔 것이 아니라 방금 나온 숫자에서 만든다.

위에서 칸을 하나 누르면 결과가 여기에 나온다.
